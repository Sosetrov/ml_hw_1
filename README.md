# Программные инструменты анализа данных в задачах информационной безопасности. Домашняя работа 1 (hw_1)

## 1. Постановка задачи

### Бизнес-постановка

Исследование признаков URL и соответствующих веб-страниц для подготовки прототипа системы, которая определяет потенциально фишинговые адреса. Такая система может быть частью почтового шлюза, браузерной защиты или сервиса проверки ссылок.

### Постановка ML-задачи

Задача относится к бинарной классификации. По набору характеристик URL/веб-страницы требуется определить класс адреса: фишинговый или легитимный. Целевая переменная — `label`: по документации UCI `0` означает фишинговый URL, а `1` — легитимный URL.

### Датасет

Используется **PhiUSIIL Phishing URL (Website)** из UCI Machine Learning Repository: https://archive.ics.uci.edu/dataset/967/phiusiil-phishing-url-dataset.

По описанию UCI, набор включает 235 795 записей, 56 признаков и не содержит пропущенных значений. В опубликованном описании приведено 134 850 легитимных (57,19%) и 100 945 фишинговых URL (42,81%). Классы не идеально сбалансированы, но сильного дисбаланса по одним лишь численностям нет. Признаки включают характеристики URL и домена, а также сведения, извлечённые из содержимого веб-страницы.

## 2. Выбор метрик

В качестве основных метрик будущей модели использовать **Recall для класса «Фишинговый URL»**, **Precision** и **F1-score**.

Recall показывает, какую долю фишинговых ссылок система обнаруживает; низкое значение - значительная часть опасных ссылок остаётся невыявленной. Precision показывает, какая доля ссылок, помеченных системой как фишинговые, действительно относится к этому классу; F1-score помогает совместно оценить Precision и Recall.
Такие метрики выбраны, так как false-negative (пропущенный фишинг) дороже, чем false-positive (легитимный сайт, принятый за фишинг), поэтому надо максимизировать Recall. Дополнительно можно будет использовать FPR для контроля доли ошибочно заблокированных легитимных сайтов
